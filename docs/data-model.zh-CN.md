## Run / Agent / Turn

记录到的活动按三个嵌套层级组织：

- **Run（运行）** —— 一次逻辑执行（一次 AI 会话）。可以包含一个或多个智能体。
  没有子智能体的普通对话恰好包含一个智能体；派生了 Task 子智能体的编排者则包含父级
  加上所有后代，它们通过 provider 原生的父/子标记相互关联。
- **Agent（智能体）** —— 一个对话上下文。对应单个转录文件（Claude Code 中即一个
  `.jsonl`）。拥有模型、工作目录、标题和一组回合。
- **Turn（回合）** —— 一次 **API 调用**（一次 LLM 请求/响应）。

子智能体是从 provider 自身的数据中识别出来的 —— 对 Claude Code 而言就是
`<parent>/subagents/agent-*.jsonl` 这一目录约定。不用启发式规则，不做内容嗅探。
如果某个框架没有在转录文件之间记录父子关系，那么每个转录文件就是一个单智能体运行；
这是正确行为，不是缺陷。

## 准确性说明

**Token 去重。** Claude Code 会为响应的每个 *content block* 写一行 JSONL，而每一行都
重复着同样的 `usage` 数字。回合按响应的 `message.id` 去重，因此每次 API 调用恰好只
计一次。若不做去重，真实转录文件的输出 token 会被高估约 2.4 倍（工具调用密集的会话
更多）。所有总量、图表和成本估算用的都是去重后的数字。

**失败的调用。** 以模型 `<synthetic>` 记录的错误回显不计入统计，也不进入模型列表；
它们在会话树中显示为错误节点。

**日期边界。** "今日"和按天分桶使用你所在时区的自然日，而非 UTC。

**标题。** 运行标题优先取自转录文件的 `ai-title` 记录（Claude Code 自己生成的 AI 会话
标题）；没有时则取第一条真实用户提示词，并剥离 IDE/框架的包装标签。

**缓存写入 TTL。** 5m/1h 的拆分来自 `usage.cache_creation`。仅带总量的历史记录会被
归入 5m 桶（默认 TTL），以免高估成本。

**记录值 vs 估算值。** 触发次数、工具调用和 skill 调用来自解析后的事件流 —— 是实际
记录的，不是推断的。UI 中任何标注 *est.* 的数字（MCP/skill token 用量、注入提示词
成本）都是分词器估算值。

## 数据库

SQLite，位于 `data/cache.db`，WAL 模式。共五张表，每张都带一个 `provider` 列以支持
多数据源。

| 表 | 一行代表 | 说明 |
|---|---|---|
| **`files`** | 一个转录文件 | 路径 + 字节偏移，用于增量解析 |
| **`runs`** | 一次逻辑运行 | 派生的汇总：标题、工作目录、智能体数、回合数、首次/最后出现时间。每次全量扫描**以及**每次增量摄入（防抖）后都会重建，因此 Runs 页面无需重启即可保持实时 |
| **`agents`** | 一个转录文件 | `run_id`、`parent_agent_id`、`parent_turn_index`（同级排序）、`agent_type`、`description`（来自子智能体的 `meta.json`）、标题、工作目录、最后出现时间、回合数 |
| **`turns`** | 一次 API 调用 | **(agent_id, message_id) 唯一** —— 正是这个索引消除了"每个 content block 一行"格式带来的重复。携带模型、token 计数、时间戳，以及 `bucket` 列（0 = 基础，1 = MCP，2 = skill，解析时根据该次调用的 `tool_use` 块判定；子智能体归属用 `is_subagent`） |
| **`events`** | 一个已解析事件 | 按 (agent_id, 源 uuid) 幂等：用户提示词、工具调用（含工具名与 `tool_use_id`）、hook 触发、API 错误、上下文压缩、模型回退。工具事件还携带估算的 token 体积，Skill 调用另带 skill 名称 |

`turns` 是 token 总量、回合数和最后出现时间的事实来源 —— 这些值全部由它重新计算，
绝不信任任何手工维护的计数器。（否则，增量解析 `ai-title`、`mode` 或 `summary` 这类
末尾无时间戳的记录时，会把回合数清零或把 `last_seen_at` 置空。）

**Schema 版本。** schema 版本存放在 `PRAGMA user_version` 中。应用启动时若发现版本不
一致，就会丢弃并重建所有表，然后重新解析全部转录文件。删除 `data/cache.db` 会触发
同样的重建。任何时候重建都是安全的：JSONL 转录文件才是唯一的事实来源。

## 成本估算

这里的成本是 **API 等价参考值**，不是账单。每个回合的 token 按一张分模型价格表
（每百万 token 的 输入 / 输出 / 缓存写入 / 缓存读取 单价）计价，你可以在 **Settings**
页面或直接在 `data/pricing.json` 中编辑。缓存写入按输入价的 1.25 倍（5 分钟 TTL）或
2 倍（1 小时 TTL）计价；缓存读取按输入价的 0.1 倍计价。

如果你用的是 Pro/Max 订阅，这些数字告诉你同样的工作走 API 会花多少钱 —— 它们不是你
实际被收取的金额。Anthropic 没有提供查询订阅席位用量的程序化 API；那部分请见
<https://claude.ai/settings/usage>。
